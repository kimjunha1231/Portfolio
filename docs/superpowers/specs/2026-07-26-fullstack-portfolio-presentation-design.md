# 풀스택 개발자 포트폴리오 PPT 디자인 명세

## 목적과 독자

- 목적: 국내 기업 서류 제출용 풀스택 개발자 포트폴리오
- 1차 독자: 채용 담당자와 개발 조직의 실무 검토자
- 언어: 한국어
- 핵심 인상: 문제를 측정하고, 기술적 판단을 내리고, 구현 결과를 검증하는 개발자
- 읽기 방식: 발표 설명 없이도 각 슬라이드가 독립적으로 이해되는 제출형 문서

## 내러티브 전략

포트폴리오는 성과 중심 에디토리얼형으로 구성한다. 프로젝트마다 단순한 기능 목록 대신 아래 흐름을 반복한다.

1. 해결하려던 사용자·운영 문제
2. 관찰과 측정으로 확인한 원인
3. 선택한 기술과 대안 판단
4. 구현 범위와 담당 역할
5. 수치 또는 운영 결과로 확인한 변화

대표 프로젝트는 JobSecretary와 Smart Messaging System을 가장 깊게 다룬다. Dearfam과 TITO는 기술 전환, 리드 경험, 실시간 통신, 출시 성과를 보여주는 보조 사례로 사용한다. 나머지 프로젝트는 기술 범위와 성장 과정을 보여주는 압축 타임라인으로 정리한다.

## 슬라이드 구성

1. 표지 — 문제를 측정하고 구조로 해결하는 풀스택 개발자 김준하
2. 핵심 역량과 대표 성과 — 렌더링, API, 접근성, 수상·출시 성과
3. 프로젝트 지도 — 웹·앱·백엔드·AI·데이터 관점의 프로젝트 분포
4. JobSecretary 개요 — 사용자 문제, 1인 개발 범위, 기술 스택
5. JobSecretary 성능 문제 — 프로파일링 결과와 원인 분석
6. JobSecretary 기술적 판단 — 드래그 라이브러리 교체, 렌더링 격리, FSD 구조
7. JobSecretary 검증 결과 — 커밋 271회에서 98회, 비활성 리렌더링 268회에서 0회, 접근성 95점대
8. Smart Messaging System 개요 — 마케터 메시징 흐름과 담당 범위
9. 고객 조회 병목 분석 — 목록·상세 책임 혼합과 N+1 문제
10. 조회 성능 개선 — API 86.7% 감소, 응답 크기 99.8% 감소 등 전후 비교
11. Redis Draft 설계 — 임시 선택 상태, Sorted Set, TTL, Pipeline의 선택 이유와 트레이드오프
12. Dearfam — Flutter MVP에서 React·TypeScript 웹 서비스로의 전환과 병렬 개발
13. TITO — REST API와 WebSocket 역할 분리, 프론트엔드 리드, 앱 마켓 배포
14. 확장 경험 — POPPET, 여행의 이유, SSYUNG과 수상·협업 경험
15. 마무리 — GitHub, 포트폴리오 사이트, 연락처, 한 문장 정리

## 시각 방향

- 전체 톤: 밝고 차분한 기술 에디토리얼
- 배경: 오프화이트와 아주 옅은 회색
- 본문: 차콜·딥 네이비
- 포인트: 블루, 민트, 제한적인 웜 옐로
- 타이포그래피: Pretendard 또는 호환 가능한 한국어 산세리프
- 레이아웃: 넓은 여백, 큰 제목, 한 슬라이드 한 메시지, 실제 프로젝트 이미지 중심
- 장식: 얇은 규칙선, 작은 페이지 번호, 에디토리얼 캡션
- 지양: 과도한 글래스모피즘, 네온 그라데이션, 카드 격자 남용, 불필요한 아이콘, 생성형 AI 특유의 복잡한 장식

## 이미지 사용 원칙

- GPT Image 2 생성 이미지는 표지용 밝은 3D 아이소메트릭 아트워크 1점에 한정한다.
- 생성 이미지에는 텍스트·로고·가짜 UI를 포함하지 않는다.
- 본문은 저장소의 실제 제품 화면, 성능 측정 화면, 로고·모바일 목업을 우선 사용한다.
- 성능 전후 비교와 아키텍처는 PowerPoint 기본 도형과 실제 캡처를 사용해 검증 가능성을 유지한다.
- 모든 외부 자료와 생성 이미지의 출처 또는 생성 사실을 슬라이드 발표자 노트에 기록한다.

## 콘텐츠 원칙

- 성과 수치는 저장소 MDX와 실제 프로젝트 자료에 있는 값만 사용한다.
- 측정 조건이 없는 수치를 새로 만들거나 추정하지 않는다.
- 개인 프로젝트와 팀 프로젝트의 역할·기여도를 명확히 구분한다.
- 기술 스택은 나열보다 해당 문제에서 선택한 이유와 연결한다.
- AI 기능은 사용자 판단을 보조하는 범위와 실제 개발 책임을 명확히 표현한다.

## 완료 기준

- 15장 모두 발표 설명 없이 이해 가능하다.
- 각 대표 프로젝트에 문제, 원인, 판단, 구현, 결과가 포함된다.
- 최소 3개 이상의 정량적 성과가 시각적으로 명확하다.
- 실제 프로젝트 이미지가 생성 이미지보다 압도적으로 많은 비중을 차지한다.
- 모든 슬라이드를 렌더링해 텍스트 잘림, 겹침, 흐린 이미지, 잘못된 크롭을 수정한다.
- 오버플로 검사와 전체 슬라이드 시각 검토를 통과한 최종 PPTX만 전달한다.
